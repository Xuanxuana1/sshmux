# Directory Structure

> Standard Go project layout for the sshmux CLI tool.

---

## Project Layout

```
sshmux/
├── cmd/
│   └── sshmux/
│       └── main.go          # Entry point — cobra root command + subcommand wiring
├── internal/
│   ├── ssh/                 # Layer 1: SSH master connection (ControlMaster)
│   │   ├── master.go        # Connect / disconnect / status via ssh -MNf
│   │   └── master_test.go
│   ├── proxy/               # Layer 2 & 3: SOCKS + HTTP proxy management
│   │   ├── socks.go         # SOCKS DynamicForward: on / off / set-port
│   │   ├── http.go          # Privoxy process: start / stop / reload config
│   │   └── proxy_test.go
│   ├── state/               # JSON state persistence
│   │   ├── store.go         # Read / write / update HostState
│   │   ├── types.go         # HostState struct
│   │   └── store_test.go
│   ├── config/              # SSH config file parsing
│   │   ├── parser.go        # Parse ~/.ssh/config + resolve Include directives
│   │   └── parser_test.go
│   └── macos/               # Layer 4: macOS system proxy integration
│       ├── proxy.go         # networksetup wrapper (SOCKS / WebProxy / SecureWebProxy)
│       └── proxy_test.go
├── go.mod
├── go.sum
└── README.md
```

---

## Package Responsibilities

| Package | Responsibility | External calls |
|---------|---------------|---------------|
| `cmd/sshmux` | CLI flag parsing, subcommand dispatch, user-facing output | — |
| `internal/ssh` | SSH master lifecycle via ControlMaster | `ssh` binary |
| `internal/proxy/socks` | Add/remove DynamicForward via ControlMaster socket | `ssh -O forward/cancel` |
| `internal/proxy/http` | Manage Privoxy child process and config file | `privoxy` binary |
| `internal/state` | Atomic JSON read/write for HostState | filesystem only |
| `internal/config` | Parse OpenSSH config files and Include trees | filesystem only |
| `internal/macos` | macOS system proxy settings | `networksetup` binary |

---

## Key Principles

1. **`cmd/` is thin** — it parses flags, calls `internal/`, prints results. Zero business logic.
2. **`internal/` packages are independently testable** — no circular imports; external binaries are called through an injectable interface.
3. **No `pkg/`** — this is a single-binary CLI, not a library. Everything lives under `internal/`.
4. **One layer per package** — `ssh`, `proxy`, `state`, `config`, `macos` map directly to the four architectural layers in `prp.md`.

## External Binary Interfaces

All shell-outs are defined as Go interfaces so tests can inject fakes:

```go
// internal/ssh/runner.go
type CommandRunner interface {
    Run(name string, args ...string) error
    Output(name string, args ...string) ([]byte, error)
}
```

Production code uses `exec.Command`; tests inject a stub that records calls.
